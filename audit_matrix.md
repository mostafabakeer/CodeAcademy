# Code Audit Matrix - DR Code Admin Panel

| **رقم** | **وصف المشكلة** | **درجة الخطورة** | **الأثر على الباك إند والأداء** | **طريقة الإصلاح المقترحة** |
|----------|-------------------|-------------------|----------------------------------|---------------------------|
| 1 | **`toggleSubscription` async/await issue with `run` helper** (行 225-236) | **Critical** | Calling `await run(...)` with an `async` `onOk` callback causes the WhatsApp message to open prematurely or race with `patchStudent`. The `run` function calls `onOk?.()` without awaiting its returned Promise, breaking the activation sequence. | Refactor `toggleSubscription` to handle the WhatsApp open outside `run`'s `onOk`, or make `run` properly await async `onOk` callbacks. |
| 2 | **`run` helper busy state not cleared on component unmount** (行 201-213) | **Medium** | If the Admin panel unmounts while a `run` operation is in progress, the `busy` state key remains set indefinitely, leaving buttons in a permanently disabled state until the next operation. | Add cleanup logic in `useEffect` return function or implement an operation abort mechanism when the component unmounts. |
| 3 | **`refresh` function doesn't use `run` helper** (行 181-191) | **Medium** | The `refresh` function directly calls `api` without busy-state management, allowing double-refresh clicks and providing no visual feedback until the API resolves. | Refactor `refresh` to use the `run` helper consistently with other toggle functions. |
| 4 | **Cache stale data potential** (行 80-91) | **Low** | The cache TTL check `Date.now() - parsed.at > CACHE_TTL` could serve stale data if `parsed.at` is corrupted or the cache structure changes unexpectedly. | Add robust cache validation and versioning; fallback to API if cache format is unrecognized. |
| 5 | **`openWaForMessage` could open invalid WhatsApp links** (行 258-261) | **Low** | If `toWhatsappNumber()` produces an unexpected format, the `window.open()` call may open a broken or unexpected WhatsApp link, degrading UX. | Add phone number validation before opening the link; show error if invalid. |
| 6 | **`loadResetRequests` uses hardcoded `run(0, 'resets', ...)** (行 263-267) | **Low** | Using `0` as the ID for the `busy` state key could conflict with other operations if the app scales; also makes the code less readable. | Use a descriptive constant or unique identifier like `CACHE_KEY` or `RESET_REQUESTS_KEY`. |
| 7 | **`approveReset`/`rejectReset` button busy state key mismatch** (行 406-425) | **Low** | The busy state key `isBusy(r.id, 'approve')` uses the reset request ID, which could conflict if requests are reloaded with new IDs, causing button states to not reset properly. | Clear busy state keys when reloading requests, or use a stable prefix. |
| 8 | **No global error boundary for API failures** (Throughout) | **Medium** | Individual API calls have `.catch()` but no global error boundary. Critical UI states could be left in error mode without proper user feedback or recovery options. | Implement a global Error Boundary component that catches API errors and displays user-friendly messages with retry options. |
| 9 | **Inconsistent `run` helper usage** (Throughout) | **Medium** | `toggleRole` and `toggleBlock` use `run` correctly, but `toggleSubscription` has the async issue, and `refresh` bypasses it entirely. This inconsistency increases cognitive load and bug risk. | Standardize all admin actions to use the `run` helper uniformly, or document when it's appropriate to bypass it. |
| 10 | **Debounced query stale values** (行 116-119, 158-172) | **Low** | The 400ms debounce timeout means `filtered` state could have stale values during the debounce window, causing search results to lag behind user input. | Reduce debounce time to 150-200ms, or use `useEventListener` + `requestAnimationFrame` for smoother updates. |
